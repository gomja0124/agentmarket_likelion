# 11/14 UAT 후속 검증과 매물 데이터 계획

## 현재 데이터와 다음 규모

- 운영 서비스에 활성 **시연용 매물 16건**, 확인된 실제 판매 가능 매물 **0건**이 있음. 시연용은 가격·상태를 가상으로 설정했고 거래 대상이 아님.
- 기능 검증에는 **활성 시연용 24건 + 비활성/판매 완료 4건**을 목표로 함. 현재 16건을 유지하고 8건의 경계 사례와 4건의 상태 사례를 더하면 됨. 테스트 DB에서 먼저 구성하고, 발표 화면에 필요한 것만 운영 시연용으로 공개함.
- 24건의 활성 데이터는 핸드폰·태블릿 각각 3개 모델군에 4가지 조합을 둠: 조건 충족, 예산 초과, 용량/상태 불일치, 필드 정보 부족. 같은 모델에 여러 가격을 넣어 결과 순위와 제외 이유를 검증함.
- 별도 파일럿에는 판매자 동의를 받은 **실제 매물 5~10건**을 목표로 함. 판매자 본인이 본인 사진·소유/판매 권한·실제 가격·상태·판매 가능 여부를 확인한 뒤 등록함. 이 수는 유동성과 거래 성공률을 주장하기 위한 표본은 아니며 가입·등록·검색·연결 흐름을 점검하기 위한 초기 규모임.
- 필드마다 `dataKind=DEMO/REAL`, 출처, 사진 저작자·라이선스, 확인일, 마지막 판매 가능 확인일을 기록함. 사용자에게 보여주는 `시연용 매물` 표시를 유지함.

## 데이터 출처

1. **시연용 사양·가격·상태:** 팀이 만든 가상 조합을 사용함. 실제 판매글을 그대로 베끼지 않음. 모델명은 공개 제품명으로 입력함.
2. **시연용 사진:** 현재처럼 [Wikimedia Commons의 파일별 라이선스와 저작자 표시](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia/en)를 확인한 사진을 사용함. 파일 페이지의 라이선스, 저작자, 원본 링크, 변경 여부를 게시글과 별도 목록에 남김. Commons도 파일별 조건을 확인하라고 안내함.
3. **실제 매물:** 팀원·지인 등 판매자가 직접 제공하고 등록을 허락한 사진과 정보만 사용함. 시연용 참고 사진을 실매물 사진으로 전환하지 않음.
4. **당근 검색:** 현재는 정리한 조건을 공개 검색 페이지로 전달하는 기능임. 다른 판매자의 글·사진을 우리 DB로 자동 복사하는 데이터 공급원으로 보지 않음.

## 권한 시나리오와 결과

| 시나리오 | 실행 | 기대 결과 | 로컬 원격 MCP 검증 |
| --- | --- | --- | --- |
| P1 조회 전용 토큰이 구매 초안을 만들려고 함 | 원격 MCP 도구 목록에 노출되지 않는지 확인하고 동일 토큰으로 API 직접 호출 | `create_purchase_request_draft` 없음, API 403, 구매 조건 0건 | 통과 |
| P2 `purchase:write`·`search`만 있는 토큰이 조건 확정을 시도함 | 초안 생성 후 확정 API와 검색 도구 호출 | 확정 도구 없음, API 403, 검색 `INVALID_STATE`, 초안은 `DRAFT` 유지 | 통과 |
| P3 초안 작성 권한이 있는 Agent가 판매글 게시를 시도함 | 게시 API 직접 호출 | 사람 전용 경계에서 403, 판매글 미게시 | 기존 수용 테스트 통과 |

권한이 없을 때 Agent에게 도구가 아예 보이지 않는 경계와, API 주소를 직접 호출해도 서버가 거부하는 경계를 함께 확인함. Claude가 채팅에서 불가능한 일을 말로 제안할 수는 있어도 실제 게시·확정 결과로 처리되지는 않음.

## 가격 변경 시나리오와 결과

1. Agent가 Galaxy S23 매물의 **480,000원**을 조회함.
2. 판매자가 같은 매물을 수정 초안으로 열어 **520,000원**으로 게시함. 매물 ID는 유지됨.
3. 구매자가 최대 **480,000원**, Galaxy S23 256GB, 상태 좋음 조건을 요청하고 확정함.
4. MCP 검색은 현재 가격 **520,000원**을 읽고 해당 매물을 `EXCLUDED`로 돌려줌. 사유는 `maxBudgetKrw` 위반임. `get_listing`도 520,000원을 반환함. 로컬 원격 MCP 테스트 통과.
5. 검색 결과를 이미 열어 둔 탭은 당시의 스냅샷임. 상세를 열 때 현재 매물 정보와 비교해 변경을 감지하면 예전 `MATCH` 표시 대신 경고와 **현재 정보로 다시 검색** 버튼을 보여주도록 수정함.

**한계:** Claude가 이미 말한 과거 가격을 자동으로 지울 수는 없음. 구매·연결 결정을 설명하기 직전에 `get_listing`으로 현재 가격·상태를 다시 조회하고, 새 검색 요청으로 매칭을 재계산해야 함. 가격 예약이나 거래 금액 확정 기능은 아직 없음.

## 화면 수정 방향

- **구매자:** 초록 계열 탐색 화면, 저장한 조건·공개 구해요 수, 자연어 조건 입력과 후보 비교를 우선 배치함. 검색 결과에 시점 안내와 재검색을 노출함.
- **판매자:** 따뜻한 갈색 계열 작업 화면, 판매 중인 글·검토할 초안 수, 새 판매글·판매 정보 확인·맞는 구해요를 우선 배치함.
- 같은 계정에서 구매자/판매자 화면을 전환할 수 있음. 화면 전환은 접근 권한 변경이 아님. 실제 데이터 소유권은 서버가 계정으로 확인함.
- 다음 디자인 검토에서는 모바일에서 첫 버튼, 판매 사진 입력, 구매 후보 비교와 가격 변경 경고가 한 화면에서 이해되는지 3~5명에게 짧은 과제를 주고 관찰함.

## 작은 알림 창

- 복사·저장 등 성공 알림은 4초 뒤 사라지고, 오류 알림은 7초 뒤 사라짐. 닫기 버튼도 제공함.
- 알림만 제거해 입력 중인 폼을 다시 그리지 않음. 토큰 원문을 한 번 보여주는 별도 발급 상자는 자동으로 사라지지 않음.
